# Starboard v0.18.0

Released 15 November 2026.

## Added

- **Update now and automatic updates.** Settings, Updates has Update now, which asks for your Starboard password and installs the newest release, showing each step as it goes. Install Starboard updates automatically (deactivated until you activate it) installs a new release by itself in quiet hours and does not try a version again after it did not install. Reelix's automatic updates wait for quiet hours too, and both set-ups ask about updates after Download hours.
- **Recommended plug-ins.** The Catalogue starts with a Recommended group: Direct play, Notifications and Disk forecast, each with a Recommended chip. Direct play gets films and episodes ready to play on every device without converting them as you watch. Nothing is added until you choose it, with what it may do and your password as before.
- **Plug-in logos.** A plug-in can have a small logo, which Starboard checks and cleans before it shows it in Manage, the Catalogue, the plug-in's page and its dashboard cards; a plug-in without one shows its initials.
- **Plug-in jobs on your schedule.** A plug-in's job can run when you choose in its settings: every day, every week on a day, or every month on a date, at a time. System, Jobs shows when it runs next, with Run now.
- **Plug-ins for Jellyfin's pictures.** A new permission lets a plug-in read and change Jellyfin's metadata folder (its posters, photos and details). It is said plainly before you add the plug-in, with a medium risk, and nothing else gets the folder.
- **Plug-in updates you can trust.** Before a plug-in updates, its warning shows What is new since your version, which of your settings move and how the update is kept safe. The update then runs as steps you can follow: the plug-in finishes its work first, your settings move to the new version, and Starboard waits for the new version to answer. If it does not, Starboard goes back to the version you had by itself, with your settings as they were, and says why.
- **Plug-in API 1.14.** For plug-in makers: logos, the card band, a card's own refresh time (10 seconds at the quickest), job schedules from settings, the jellyfin:metadata permission, and update tools: a step before and after an update, settings migrations kept for Roll back, a health wait with an automatic Roll back, and What is new before an update. Plug-ins made for earlier versions work as before.
- **Starboard's API 1.2.0, updates.** A key with Updates ticked (never given unless ticked) can list what can be updated, start an update to the version Starboard already found, follow its steps and roll a plug-in back, with an Idempotency-Key and a line in the audit log. One update runs at a time, with the same backup, health check and way back as the pages.
- **A new help centre.** The help has a home page with the journey from first install to everyday use, a side menu of areas and groups on every page, the newest change, and a problem solver that asks what is wrong and leads to the answer. Every Fix a problem topic starts with a flow chart. New topics cover updating Starboard, plug-ins, Reelix and apps, and going back.
- **Accessibility in the help.** The help has its own Accessibility section: how to change Starboard to suit you (text size and spacing, contrast, reduce motion, underlined links), ways to use it (a keyboard, a screen reader, zoom, a phone or tablet), and how it is checked, with the latest results, the known gaps and how to tell us about a problem.

## Changed

- **Plug-in cards look the same.** Every plug-in card on the dashboard has a grey band across the top with the plug-in's logo, its name as the heading, and at the right a status and when it last updated.
- **Updates hand over to the new version.** update.sh hands over to the new version's own update.sh, so a fix to it helps in the very update that brings it. Going back keeps the running copy.
- **What is new fills the width.** In the upgrade guide, What is new now fills the slide-out's width on wide screens instead of leaving an empty strip.

## Fixed

- **Large text in the side menu.** At 125% to 175% text, and with wider spacing, the side menu grows wider, so Starboard no longer breaks in the middle of the word and Feedback no longer runs past its edge.
- **Large text in the header.** When the header has too little room it gives way in steps: icons only, then the Search button, then Help and Display as icons, then the menu under Menu. Nothing is cut off and the search box is never squeezed to a few letters.
- **Short windows and phones.** In a window about 600 pixels tall the side menu items no longer overlap, and the menu scrolls on its own when they still do not fit. On a phone at 150% and 175% text, Downloads no longer scrolls sideways.
- **Reduce motion Off.** Off now brings back all movement even when your device asks for reduced motion; Match device follows the device and On always reduces it.

## Security

- **Updates need your password or their own scope.** Update now asks for your Starboard password, and an API key can start updates only when Updates was ticked when it was made; each update is in the audit log.
- **Logos are cleaned before they show.** A plug-in's logo is checked and cleaned by Starboard (no scripts, links or outside files) before any page shows it.
- **Jellyfin's pictures only when you approve.** Only a plug-in with the jellyfin:metadata permission, approved when you add it, can reach Jellyfin's metadata folder.
- **Checks.** The unit tests, the browser journeys, the accessibility checks (axe, reading order, keyboard tasks and the new layout check), the API contract tests and example plug-ins, the help check, the private details check and the full security scans, with CodeQL, ran on this release.

## Your settings and the way back

Nothing changes in your settings: Install Starboard updates automatically stays deactivated until you activate it. To go back, run ./update.sh --to v0.17.0.
