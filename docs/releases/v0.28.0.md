# Starboard v0.28.0

Released 23 November 2026.

## Added

- **Two-step code and single sign-on for Starboard's own sign-in.** Settings, Security, Sign-in methods: a two-step code and single sign-on with any OpenID Connect provider, both off until you set them up. Single sign-on does not ask for the two-step code, and Starboard's help says which claims are safe to match on.
- **A hardware video conversion check.** System, Overview has a Hardware video conversion panel that tests VAAPI, Intel Quick Sync, NVIDIA NVENC and software through Jellyfin's own ffmpeg, only when asked, and says what to fix for each that does not work.
- **Help pictures: at least 3 in 42 more topics.** 129 new marked-up screenshots from made-up data, so 42 more topics have at least 3 pictures.
- **The developer help follows the code.** The plug-in manifest reference names every field the check accepts, tests keep it so, and llms-full.txt holds the developer pages in one file for AI tools.

## Changed

- **A resting plug-in is never stopped while it works.** A plug-in that starts when needed now counts processor time as use as well as network traffic, so one that is converting a file stays up until it finishes.
- **About, redone.** Settings, Updates, About has a section on every accessibility feature and a section on how lean Starboard is, with figures measured on the server.
- **The bug report form says where to find the version.** The version box now says Settings, then Updates, then About.

## Security

- **Single sign-on needs https.** The provider's address must be https, except for this computer itself (loopback), which is allowed for testing.
- **Junk requests cannot lock the owner out of the two-step step.** A flood of junk requests can no longer use up the tries of the two-step step, so it cannot lock the owner out.
- **The saved client secret is cleared when the provider changes.** Changing the single sign-on provider clears the client secret saved for the old one, so it is never sent to a new provider.
- **Single sign-on has its own limiter.** Single sign-on has its own limit on tries, apart from the password's, so one cannot use up the other.
- **One pinned address lookup, with an overall deadline.** The provider's name is looked up once and that address is connected to, with one overall time limit, so DNS rebinding and slow-drip servers are refused.
- **Sign-in starts are limited for each address.** Starting a sign-in is limited for each address, so one address cannot push other people's started sign-ins out.
- **Provider text is cleaned in logs.** Text that comes from the provider has control characters removed before it is written to a log, so it cannot forge log lines.
- **The provider connection refuses TLS older than 1.2.** The connection to the sign-in provider refuses TLS versions older than 1.2 (a CodeQL finding).
- **Security scan.** Trivy (image and configuration), Gitleaks, Bandit, ShellCheck, Hadolint and ZAP signed out (58 passed) and signed in (112 passed) found nothing to fix.

## Your settings and the way back

Your settings stay as they are. Two-step code and single sign-on are off until you set them up. To go back, run ./update.sh --to v0.27.0.
